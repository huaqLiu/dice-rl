# 采集稳定性收尾与明日验收

完成时间：2026-10-30。目的：解决 JPEG 编码或写盘短暂停顿直接拖慢 10 Hz 采样的问题。

## 已完成的行为

- 定时采样线程只做观测时效/配对检查、观测复制与入队；后台线程负责准备/编码、HDF5 写入及磁盘检查。
- 默认队列上限 20 帧，图像副本占用上限约 74 MB，另有接收缓存及正在处理的帧。复制后的观测不受传感器复用数组影响。
- 保留 10 Hz、双路 224×224 策略图、原始 RGB、实际/目标位姿与夹爪字段，既有转换器可以直接读取。
- 采样本身超期、队列满、传感器超时和配对失败仍会中止；没有跳帧补齐或放宽原有效性阈值。
- 停止后先写完全部已采帧，再关闭文件、释放录制锁。保存期间禁止开始下一条或复位。
- 编码/写盘线程失败时保留 `trajectory.partial.h5` 和 invalid 标签；已完整写出的中止片段仍标 invalid，不进入正式训练。
- 界面显示“已采 / 已写 / 待写”。每条新增 `timing.jsonl`，`metadata.json.performance` 保存平均/最大耗时和队列观察峰值。
- `wall_timestamp` 记录实际采样阶段的主机时间，而非后台延迟写入的时间；固定采样时间和各源时间戳继续保留。

本次没有向机械臂发送指令，没有修改原始真机示范、既有标签或控制器参数。重启采集程序后新代码才会生效。

## 验证结果

完整回归复跑 **98 项通过，39.11 秒**。另单独运行 ROS 相关 28 项及其余 70 项，均通过。

首次将全部测试混合运行时曾在 ROS 测试阶段发生原生进程崩溃（exit 139）。后续分组与完整复跑均通过；崩溃根因尚未确证，不将其表述为已定位修复。全部测试使用临时数据或隔离 ROS 域，不驱动真机。

使用既有图像作离线输入回放，原始尺寸为 D435i 640×480、Femto Bolt 1280×720；回放产物均标记 simulated，并单独放在 log_dir 下。

## 明天怎么验收

1. 关闭旧采集窗口，按原流程确认机器人驱动和阻抗控制器就绪；准备采集时减少并行高负载任务。
2. 重启采集，无需编译 ROS：

   ```bash
   cd /home/lhq/dice-rl/my_dice_rl
   bash script/collect.sh
   ```

3. 先录几条短示范。观察“待写”是否能回落；结束后等到“已采＝已写”、状态显示保存完成，再复位或开始下一条。
4. 若仍中止，保留该条的 `metadata.json` 和 `timing.jsonl`，区分采样调度、观测快照、队列积压及编码/写盘错误；不要直接把 invalid 改成 success。
5. 现场确认稳定后继续累计 50 条有效成功示范。

传感器实际断流、整个进程长时间得不到调度或存储持续跟不上，仍会触发中止；有界队列不能消除这些根因。
